按现象排错

编译失败

在输出窗口向上找到第一条包含 error: 的报错，连同文件名、行号和附近几行一起保存。末尾的 exit status 1 只表示编译失败，具体原因在它前面。

报错或现象 检查方法
Adafruit_SSD1306.h: No such file 在库管理器中安装 Adafruit SSD1306 及其依赖。如果交替使用 IDE 和命令行，核对编译时使用的库目录。
找不到 Wire.h 确认已安装 Espressif 的 ESP32 开发板软件包，并在 IDE 中选中所用板型。
SCREEN_ADDRESS 附近出现语法错误 打开草图，检查这行是否写了地址值。课程基础草图写的是 0x3C。
找不到 ledcAttach 或 ledcSetup 查看 Arduino-ESP32 软件包版本。2.x 和 3.x 的函数名不同，课程舵机草图按版本选择调用方式。
下载开发板包或库失败 记下失败的包名和下载错误。网络恢复后重试，安装成功再编译。

上传失败或找不到串口

用可传数据的 USB 线连接开发板，拔下再插回，观察端口列表里出现了哪一项。制作课程实物时选择 ESP32C3 Dev Module 和新出现的端口，关闭其他占用该端口的串口工具后再上传。

若上传仍停在连接阶段，按手中板卡的说明进入下载模式。Windows 设备管理器若显示 USB 转串口芯片缺少驱动，按芯片型号从厂商获取驱动。

屏幕没有眼睛

  1. 断电后检查屏幕的电源、GND 和信号线。课程实物 C3 的 SDA 接 GPIO20，SCL 接 GPIO21。
  2. 打开课程包的 firmware/hardware_check/ 文件夹，把其中的 hardware_check.ino 上传到开发板。以 115200 波特率打开串口监视器。若出现 I2C device 0x3C，说明该地址有器件应答。将扫描到的实际地址与显示程序中的 SCREEN_ADDRESS 核对。
  3. 如果有应答但屏幕仍空白，查看模块背面的型号和接口。本课固件使用 128 × 64 的 I²C SSD1306。SPI 接口或 SH1106 驱动的模块还要相应修改接线和显示程序。

屏幕正常，触摸后表情不变

在实物上运行 hardware_check，观察手指碰到感应区时是否出现 TOUCH=1，松开后是否出现 TOUCH=0。若数字始终不变，检查 TTP223 的 OUT 是否接到 GPIO10。若松开后还维持高电平，核对模块的输出模式。本课用高电平有效、松手即复位的非锁存模式。

在 Velxio 中，点绿色 Touch 后松开。程序在松手时记一次触摸，等待 400 毫秒的双击窗口结束才显示笑眼。

双击被识别为两次单击

程序比较两次松开的时刻。在 Velxio 中连续做两次短按，例如让两次松手相隔约 250 毫秒。必要时在 handleTouch() 记录松手时的 millis()，根据程序时间计算间隔。若实物的 OUT 信号持续过久，先观察电平变化，再决定是否调整 DOUBLE_TAP_WINDOW。调长后，单击也得多等一会儿才会被确认。

有眼睛，串口监视器没有日志

检查端口和波特率（115200）。课程 C3 的 GPIO20 和 GPIO21 用于 I²C，同时也是这款芯片常用的 UART0 RX、TX。用板载原生 USB 接口看日志时，在 Arduino IDE 中启用 USB CDC On Boot。如果使用外接串口适配器，课程固件的非 CDC 配置将 RX、TX 分别设在 GPIO3、GPIO4。

Velxio 里有表情，舵臂停在原位

先看工程的板名。课堂上能看到两只舵臂转动的是 Tobi ESP32 DevKit V1。单击后在串口找 HEAD GPIO25=1580us，双击后找 HEAD GPIO26=1400us。如果板名是 ESP32-C3，本课所用的 Velxio 版本能记录两路脉冲输出，但画布上的 C3 舵臂保持静止。要看舵臂，打开 tobi-head-motion-esp32.vlx。双舵机画布工程和操作

打印后电路板装不进支架

先在切片器中核对单位和零件尺寸，再用卡尺量实际 PCB 和打印出的导槽，记录是槽宽、槽高还是排针位置挡住了。修改对应尺寸，按原打印方向打一小段试片，再用同一块板试插。整体缩放会同时移动面窗、安装孔和 USB 开口。测量与试片

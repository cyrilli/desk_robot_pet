5. 用长按启动学习提醒

上一章的单击和双击都会切换表情。这次加入长按手势。手指按住 1 秒，屏幕切到学习倒计时。练习先把倒计时设为 25 秒。第一轮中途取消，第二轮等到提醒出现，再轻触确认。

同一个触摸在不同状态下的作用

当前屏幕 操作或事件 接下来显示什么
普通眼睛 按住 1 秒 显示 Focus time 和剩余秒数。此时松手，计时继续。
倒计时 重新轻触并松手 取消本次计时，恢复普通眼睛。
倒计时 经过 25 秒 显示 Time for a break!。
休息提醒 轻触并松手 确认提醒，恢复普通眼睛。

长按启动那次触摸的松手和下一次轻触的松手，都让 GPIO10 回到低电平。程序要记住哪一次按下已经触发了长按，才能把这两次松手区分开。

让 coding agent 修改工作副本

在 firmware/my_pet/my_pet.ino 中加入学习提醒。按住 1 秒开始 25 秒倒计时，
开始后第一次松手，倒计时继续。计时中再次轻触并松手时取消。
到时显示休息提醒，轻触并松手后回到普通眼睛。
普通状态下保留单击、双击和上一版设置的表情时长。用 millis() 计时，
让主循环在倒计时期间继续读输入。更新操作说明，列出开始、取消、到时和确认的检查步骤。

参考固件从基础程序增加计时功能，使用基础程序的 3 秒表情时长。若从上一章自己的工作副本继续，测试时用自己设定的时长核对。参考固件 · Velxio 计时工程

主循环怎样同时计时和读触摸

参考固件把计时开始的时刻存进 focusStarted，在 updateFocus() 中判断是否到时。

if (focusActive && millis() - focusStarted >= FOCUS_DURATION_MS) {
  focusActive = false;
  focusDone = true;
  Serial.printf("FOCUS=DONE t=%lu\n", millis());
}

每轮循环都用当前时间减去起始时间。达到 FOCUS_DURATION_MS 时，程序从“计时”切到“完成”。两个时间都按无符号毫秒数计算，即使计数值在这段时间内回绕，也能算出经过的时间。如果改用 delay(25000)，主循环会停 25 秒，期间的触摸取消就无法及时处理。

另一个关键变量是 longTouchHandled。程序在确认长按时设置它。开始计时后第一次松手只清除这个标记，之后再来一次短触摸才取消计时。

用两轮输入检查四次状态变化

  1. 按住 1 秒后松手。看到剩余秒数继续变小，再轻触一次，应回到普通眼睛。
  2. 重新长按，松手后等满 25 秒。看到休息提醒后轻触确认，再试单击和双击，检查普通状态的表情和时长。

如果一松手就退回眼睛，把“按住、开始倒计时、松手”的顺序和串口里的 FOCUS 记录交给 coding agent，检查它是否把开始时的松手也算成一次取消。

两轮触摸的仿真记录

第二轮的串口记录为 FOCUS=RUNNING t=3904、FOCUS=DONE t=28905。两者相差 25001 毫秒。屏幕上的变化来自同一次仿真运行。

延长到实际使用的时间

将 FOCUS_DURATION_MS 换为 25UL * 60UL * 1000UL，即 25 分钟。先保留 25 秒的测试版本，方便改代码时重复验证。最终再按实际时长完整运行一次。参考程序把状态保存在内存中，断电重启后从普通眼睛开始。
